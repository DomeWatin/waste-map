# แผนที่จุดบริการเก็บถังขยะ — เทศบาลนครสุราษฎร์ธานี

> มือใหม่ เริ่มที่ **[INSTALL.md](INSTALL.md)** (คู่มือติดตั้ง GitHub + Neon + Render + LINE LIFF ทีละขั้น)

Google My Maps → (ตรวจทุก 3 ชม.) แปลง KML เป็น GeoJSON → Neon PostgreSQL → เว็บ Bootstrap + Leaflet
แสดงทั้ง **จุดบริการ** และ **เขตชุมชน** (พื้นที่)

```
public/index.html      หน้าเว็บ (Bootstrap 5, Leaflet, ธีมเขียว, ค้นหา, กรองชั้นข้อมูล, เขตชุมชน)
server.js              Express: /api/points.geojson, /api/zones.geojson, /api/status, /api/sync, /healthz
sync.js                สคริปต์ตรวจ+อัปเดตข้อมูล (GitHub Actions เรียกทุก 3 ชม.)
lib/                   kml.js (แปลง KML), sync.js (ตรวจการเปลี่ยนแปลง + อัปเดตฐานข้อมูล), db.js
schema.sql             ตาราง waste_points, waste_zones, sync_state, sync_log
render.yaml            Blueprint ของ Render (เว็บ)
test/                  ทดสอบตัวแปลง KML และตรรกะ sync
```

## 1) ทดสอบลิงก์ KML ก่อน (สำคัญ)
ลิงก์ส่งออกที่โค้ดใช้คือ `https://www.google.com/maps/d/u/0/kml?forcekml=1&mid=<MID>`
ซึ่ง **ยังไม่ได้ทดสอบกับแผนที่จริง** ให้รันในเครื่องคุณ:

```bash
curl -sL "https://www.google.com/maps/d/u/0/kml?forcekml=1&mid=1WyMxRL6t_FJZXkIRAyQ_UGg-xPfYz6w" | head -c 600
```

ควรเห็นข้อความขึ้นต้นด้วย `<?xml` และมี `<kml` ถ้าไม่ใช่ ให้ตรวจว่าแผนที่ตั้งเป็นสาธารณะ
หรือตั้ง `MYMAPS_KML_URL` เป็นลิงก์ KML ที่ใช้ได้จริง

## 2) รันในเครื่อง
```bash
npm install
cp .env.example .env     # ใส่ DATABASE_URL จาก Neon (ห้าม commit .env)
npm run sync             # ตรวจ/ดึงข้อมูลรอบแรก
npm start                # เปิด http://localhost:3000
npm test
```

> ถ้าเคยสร้างตารางจากเวอร์ชันก่อนหน้าไว้ใน Neon แล้ว (มีแค่ `waste_points` กับ `sync_log` แบบเก่า)
> ให้ลบก่อนรันเวอร์ชันนี้ เพราะโครงสร้างตารางเปลี่ยน (`DROP TABLE waste_points, sync_log;`)
> ถ้ายังไม่เคยรัน ไม่ต้องทำอะไร

## 3) Deploy บน Render
1. push โค้ดขึ้น GitHub (ไฟล์ `.env` ถูกกันไว้ใน `.gitignore` แล้ว)
2. Render → New → Blueprint → เลือก repo (อ่าน `render.yaml`) หรือสร้าง Web Service เองด้วยค่าเดียวกัน
3. ตั้ง Environment Variables ใน Dashboard: `DATABASE_URL` (ค่า pooled จาก Neon), `SYNC_TOKEN` (สตริงสุ่มยาว ๆ)
4. การดึงข้อมูลทุก 3 ชม. ใช้ **GitHub Actions** (`.github/workflows/sync.yml`) แทน Render Cron Job:
   ใน GitHub repo → Settings → Secrets and variables → Actions → New repository secret ชื่อ `DATABASE_URL` ใส่ connection string ของ Neon
   แล้วไปแท็บ Actions → sync-waste-map → Run workflow เพื่อรันรอบแรกด้วยมือและดูว่าผ่าน
5. workflow ต่อ Neon โดยตรง ไม่เกี่ยวกับเว็บ Render — ปล่อยให้เว็บหลับตามปกติได้ ข้อมูลยังอัปเดตทุก 3 ชม.
   ข้อควรรู้: เวลารันของ GitHub อาจเลื่อนได้ตอนคิวแน่น (ระดับนาทีถึงหลายสิบนาที) และ repo สาธารณะที่ไม่มีกิจกรรม 60 วัน GitHub จะปิด schedule ให้เงียบ ๆ
   (push/merge นับเป็นกิจกรรม) แนะนำเปิดแจ้งเตือนอีเมลของ Actions และกดรันเองเป็นครั้งคราว

สั่งตรวจ/อัปเดตด้วยมือ: `curl -X POST -H "x-sync-token: <SYNC_TOKEN>" https://<แอป>.onrender.com/api/sync`
(เติม `?force=1` เพื่อบังคับเขียนทับทั้งชุดแม้ไม่พบการเปลี่ยนแปลง)

## ระบบตรวจ "แผนที่เปลี่ยนหรือไม่" ทุก 3 ชั่วโมง
ทุกรอบ ระบบดึง KML แล้วทำตามนี้:
1. แปลงเป็นจุด/เขตชุมชน แล้วคำนวณ **hash ของข้อมูลที่แปลงแล้วทีละแถว** (ชื่อ, คำอธิบาย, พิกัด, รูป, ขอบเขต)
   — ไม่เทียบไฟล์ KML ดิบ เพราะไฟล์ดิบอาจมีค่าที่เปลี่ยนทุกครั้งโดยเนื้อหาไม่เปลี่ยน
2. **ไม่เปลี่ยน** → ไม่เขียนฐานข้อมูล แค่บันทึกใน `sync_log` ว่า "ตรวจแล้ว ไม่มีการเปลี่ยนแปลง"
3. **เปลี่ยน** → เขียนเฉพาะแถวที่เพิ่ม/แก้ และลบแถวที่หายจากแผนที่ แล้วบันทึกจำนวนเพิ่ม/แก้/ลบ
4. ถ้าแถวในฐานข้อมูลไม่ตรงกับ hash (เช่นตารางถูกล้าง) จะถือว่าเปลี่ยนและเติมกลับให้

ข้อควรระวังที่ออกแบบป้องกันไว้:
- ดึงไม่สำเร็จ / ไม่มีข้อมูลเลย → **ไม่แตะข้อมูลเดิม**
- **ข้อมูลหดเกินครึ่ง** (จุด ≥ 20 แถว หรือชุมชน ≥ 10 แถว) → ไม่อัปเดตทับ เพื่อกันกรณีมีคนลบทั้งชั้นข้อมูลโดยไม่ตั้งใจ
  แล้วเว็บสาธารณะหายไปเอง ถ้าตั้งใจลบจริงให้รันด้วย `SYNC_ALLOW_SHRINK=1`
- รอบที่รันซ้อนกัน (cron กับการสั่งมือ) ใช้การล็อกแถวสถานะ ไม่เขียนทับกัน
- หน้าเว็บแสดง "ตรวจล่าสุด …" และเปลี่ยนเป็นป้ายเตือนสีเหลืองถ้าไม่มีรอบที่สำเร็จเกิน 7 ชม. (ปรับด้วย `STALE_AFTER_HOURS`)
  ดูรายละเอียดที่ `/api/status` (`lastCheckedAt`, `lastChangedAt`, `stale`)

## ข้อมูลจริงในแผนที่ (ตรวจจากไฟล์ KMZ ที่ส่งออกเมื่อ 12 พ.ย. 2569)
- **709 จุด** ใน 4 ชั้นข้อมูล: จุดวางถังขยะทั่วไป 605, จุดแยกขยะชุมชน 53, จุดวางถังขยะคอนเทนเนอร์ 32, จุดจอดรถรับขยะ 17
  และอีก 2 จุดในโฟลเดอร์ "เส้นทางจาก จุด 21 ..." (ชื่อโฟลเดอร์ยาวมาก หน้าเว็บย่อป้ายให้อัตโนมัติ)
- **70 เขตชุมชน** ใน "เขตพัฒนาชุมชนที่ 1–4" (ที่ 1 = 23, ที่ 2 = 21, ที่ 3 = 16, ที่ 4 = 10) — 68 แห่งเป็นพื้นที่เดียว
  อีก 2 แห่งมีหลายพื้นที่แยกกัน (เก็บเป็น MultiPolygon) เส้นที่ปนอยู่ใน Placemark เดียวกับพื้นที่ถูกตัดทิ้ง
  และเส้นล้วน (เช่นเส้นทางรถ) ไม่ถูกนำมาแสดง
- 96% ของจุด (682/709) อยู่ในเขตชุมชนอย่างน้อย 1 แห่ง มี 4 ชุมชนที่ไม่มีจุดเลย (ตามข้อมูลแผนที่)
- **670 จุดมีรูปถ่าย** (หลายรูปต่อจุด) รูปอยู่บนเซิร์ฟเวอร์ของ Google: ระบบเก็บเฉพาะ URL แล้วโหลดตอนผู้ใช้กดดูจุด
  (รายการจุดทั้งหมดจึงเบา ประมาณ 400 KB, ~32 KB เมื่อบีบอัด; เขตชุมชน 65 KB, ~14 KB)
- ถ้าบางจุดไม่มีรูปแสดง อาจเป็นเพราะ Google ไม่อนุญาตให้ฝังรูปจากเว็บอื่น ยังไม่ได้ทดสอบบนเบราว์เซอร์จริง

## ฟีเจอร์เขตชุมชนในหน้าเว็บ
- สวิตช์ "แสดงเขตชุมชน" + แถบสีแยกตามเขต (เลเยอร์พื้นที่อยู่ใต้จุด จึงกดจุดได้เสมอ)
- กดพื้นที่ → ชื่อชุมชน, เขต, จำนวนจุดบริการในเขตนี้ (แยกตามชั้นข้อมูล)
- ค้นหาด้วยชื่อชุมชน → แสดงจุดทั้งหมดที่อยู่ในชุมชนนั้น และป๊อปอัปของแต่ละจุดบอกว่าอยู่ชุมชนไหน
- ถ้าโหลดเขตชุมชนไม่ได้ หน้าเว็บยังแสดงจุดได้ตามปกติ
- การนับ "จุดอยู่ในชุมชนไหน" คำนวณจากพิกัดจุดกับขอบเขตที่วาดในแผนที่ จุดที่อยู่ริมขอบหรือที่เขตซ้อนกัน
  (พบ 19 จุด) จะถูกนับในทุกเขตที่ครอบคลุม

## ถังขยะใกล้ฉัน: ปุ่มแชร์ตำแหน่ง และนำทาง
- เปิดหน้าเว็บมาจะเห็นปุ่มสีเหลืองใหญ่ **แชร์ตำแหน่งปัจจุบัน** ใต้หัวเรื่อง (เหมาะกับมือถือแนวตั้ง) กดแล้วแบนเนอร์จะซ่อน กดปุ่ม ✕ เพื่อล้างตำแหน่งและเรียกแบนเนอร์กลับ
- กด **จุดใกล้ฉัน** → เบราว์เซอร์ขอสิทธิ์ตำแหน่ง → รายการเรียงจากใกล้สุดไปไกลสุด พร้อมระยะ (ม./กม.) และเลือกรัศมีได้ 300 ม. – 5 กม. หรือ "ทั้งหมด"
  แผนที่แสดงจุดสีน้ำเงินของผู้ใช้ วงความแม่นยำ และวงรัศมี
- ระยะเป็น **เส้นตรง** (haversine) ไม่ใช่ระยะตามถนน ส่วนปุ่ม **นำทาง** (ในรายการและป๊อปอัป) เปิด Google Maps
  `https://www.google.com/maps/dir/?api=1&destination=<lat>,<lng>` โดยใช้ตำแหน่งปัจจุบันของเครื่องเป็นต้นทาง
- ตำแหน่งถูกคำนวณในเบราว์เซอร์เท่านั้น ไม่ส่งไปเซิร์ฟเวอร์
- ต้องเปิดผ่าน **https** (Render เป็น https อยู่แล้ว; `localhost` ใช้ได้) ถ้าปฏิเสธสิทธิ์/หาตำแหน่งไม่ได้ จะมีข้อความแจ้งและรายการเดิมยังใช้ได้
- ถ้าผู้ใช้อยู่ไกลเมือง จะแจ้งว่าไม่มีจุดในรัศมี พร้อมระยะถึงจุดที่ใกล้ที่สุด

## นำขึ้น LINE OA ผ่าน LIFF
โค้ดรองรับ LIFF แล้ว (ไม่บังคับ — ไม่ตั้ง `LIFF_ID` ก็ใช้เป็นเว็บธรรมดาได้):
1. push โค้ดขึ้น GitHub แล้ว deploy บน Render ให้ได้ URL แบบ `https://<แอป>.onrender.com` ก่อน
2. ใน LINE Developers Console สร้าง LIFF app (อยู่ใต้ LINE Login channel) ตั้ง **Endpoint URL** = URL ของ Render
   (ชื่อเมนู/ตัวเลือกอาจต่างจากที่เขียนไว้ ให้ดูหน้าคอนโซลจริง)
3. คัดลอก **LIFF ID** ไปตั้ง Environment Variable `LIFF_ID` บน Render (ไม่ใช่ความลับ แต่ไม่ต้อง hardcode ในโค้ด)
4. นำลิงก์ LIFF (รูปแบบ `https://liff.line.me/<LIFF ID>`) ไปใส่ใน Rich Menu / ปุ่มในข้อความของ LINE OA
- เมื่อเปิดในแอป LINE ปุ่ม "นำทาง" จะเปิดด้วย browser ภายนอกผ่าน `liff.openWindow({external:true})`
  (บทความที่ตรวจพบรายงานว่าการพาหน้า LIFF ไปเว็บอื่นทำให้ตำแหน่งใช้ไม่ได้)
- ไม่ได้ใช้ LINE Login/โปรไฟล์ผู้ใช้ จึงไม่เก็บข้อมูลส่วนตัวใด ๆ
- **ตำแหน่งในแอป LINE:** ต้องเปิดสิทธิ์ตำแหน่งทั้งระดับเครื่องสำหรับแอป LINE และตอนเบราว์เซอร์ถาม
  มีรายงานว่าบน iOS ถ้ากดไม่อนุญาตซ้ำ 2 ครั้ง จะขอสิทธิ์ใหม่ไม่ได้ (ปุ่มแชร์ตำแหน่งใหญ่ ๆ ในหน้านี้ทำหน้าที่เป็นขั้นอธิบายก่อนเบราว์เซอร์ถามจริง)
- Render แพ็กเกจฟรีจะหลับเมื่อไม่มีคนใช้ 15 นาที ผู้ใช้คนแรกหลังหลับอาจรอประมาณ 1 นาทีให้เว็บตื่น (โปรเจกต์นี้ตั้งใจปล่อยให้หลับตามปกติ ไม่มีระบบปลุก)
